연결표는 DOM 역할과 코드/청크 이름을 대조한 결과입니다. 페이지에 로드된 파일 목록만으로 해당 컴포넌트의 렌더링을 단정하지 않았습니다. 메일은 AppMuaProvider를 확인했고 별도 메일 패키지의 원본 소스는 확보하지 않았습니다.

MVP에 적용하는 순서

  1. 공통 셸과 디자인 토큰: DOM/CSS와 structure의 computed 스타일을 기준으로 서비스 메뉴·헤더·사이드바를 구현합니다.
  2. 작은 공통 UI: portable/의 InlineErrorAlert, ToneChip, OptionToggleGroup을 앱의 MUI 테마에 연결합니다.
  3. 목록·폼 계약: Table/Filter/ViewSwitcher, FormValue/PropertyFields 구조를 새 데이터 모델로 연결합니다.
  4. 도메인 폼: CustomerFormDialog·EmployeeFormDialog·DealFormDialog의 입력 인터페이스를 참고해 controller/API를 새로 연결합니다.
  5. 비동기 기능: 첨부·채팅·녹음은 업로드와 소켓·worker·권한 처리를 별도 구현하고 흐름별로 검증합니다.

원본 청크를 새 앱에서 직접 import하면 main 번들의 초기화·라우팅·전역 상태가 따라올 수 있습니다. 재사용할 함수나 UI를 읽기용 정리본에서 독립 소스로 옮긴 뒤 의존성을 교체하는 방식이 적합합니다.

미리보기 CSS 검증 범위

고객 등록 폼과 카탈로그는 브라우저에서 표시를 확인했습니다. 다른 화면은 DOM·CSS 파일 연결과 선택자 커버리지를 정적으로 확인했습니다. 화면마다 생성 시점이 다른 스타일은 다른 캡처의 원본 규칙을 보충했고, 일부는 기록된 computed 스타일에서 재구성했습니다.

메일·근태 보고서·결재 등 일부 화면에는 여전히 대응 CSS를 확보하지 못한 클래스가 있습니다. 따라서 DOM 미리보기 전체를 원본과 픽셀 단위로 동일하다고 보장하지 않습니다. 해당 구현 코드는 배포 JS에 포함되어 있습니다.
